# R-R corpus summary methodology

## Purpose

`rr-order-summary` converts the session-level JSONL emitted by `rr-order-corpus` into a deterministic,
aggregate-only report. Its job is descriptive measurement. It does not decide whether a score should be
changed or withheld.

## Input contract

- one schema-v1 `RROrderCorpusRecord` per nonblank JSONL line;
- one file from one corpus invocation;
- device keys are the runner's invocation-local pseudonyms;
- duplicate `(deviceKey, detectedStartTs, endTs)` observations fail closed;
- unsupported record schema versions fail closed;
- malformed lines report their 1-based line number.

The summary intentionally ignores `deviceID`, even when the corpus was generated with the raw-ID opt-in.

## Distribution method

Every distribution uses the deterministic R-7 linear percentile method:

```text
position = p * (n - 1)
quantile = x[floor(position)] + fractional(position) *
           (x[ceil(position)] - x[floor(position)])
```

The report includes:

- count;
- mean;
- sample standard deviation (`n - 1` denominator) when `n > 1`;
- minimum;
- p10;
- p25;
- median;
- p75;
- p90;
- maximum.

No confidence interval or p-value is fabricated. Those require an explicit sampling model and enough
independent devices, not merely many nights from one wearer.

## Weighting

Two order-coverage views are preserved because they answer different questions:

1. **interval weighted**: total qualifying intervals with the property divided by all relevant intervals;
2. **session distribution**: each session contributes one fraction, summarized across sessions.

The first describes how much stored beat data has provenance. The second prevents a single long night from
silently standing in for the whole corpus.

## Paired HRV comparison

For a session to enter the production-gated paired comparison, both the current order and magnitude-order
counterfactual must clear the existing `HRVAnalyzer` cleaning and 20-beat sufficiency gate.

The signed effect is:

```text
current RMSSD - magnitude-order RMSSD
```

The percentage effect is:

```text
(current - magnitude) / current * 100
```

A zero current RMSSD has no percentage effect and is excluded from that percentage distribution. Raw
RMSSD is summarized separately and remains diagnostic rather than production-valid.

## Descriptive exceedance bins

The report counts absolute production RMSSD differences at these fixed bins:

```text
milliseconds: 1, 2, 5, 10, 20
percent:      1, 5, 10, 20, 50
```

These are compact reporting aids. They are not clinical cutoffs, release gates, significance tests, or
score-withholding thresholds.

## Cached-value context

When both values exist, the report also summarizes:

```text
current recomputed RMSSD - cached avgHrv
```

This is context only. A cached value may have been imported, generated by an earlier release, calculated
over a different window, or preserved from a prior rescore. It is not used to validate the ordering repair.

## Privacy

The summary output contains:

- aggregate corpus counts;
- aggregate date range;
- pseudonymous per-device totals and distributions.

It does not contain:

- raw device IDs;
- R-R interval rows or sequences;
- per-session observations;
- sleep-stage segments;
- journal or workout data.

## Interpretation requirements

A behavioral HRV change still requires all of the following:

1. multiple real nights;
2. more than one device or wearer where available;
3. enough paired production-valid sessions;
4. material and reproducible effect size;
5. order-provenance coverage sufficient to explain the effect;
6. Swift/Kotlin parity;
7. downstream Charge and Readiness sensitivity;
8. a separately reviewed score or quality-policy change.
